# Tailwind Design Reviewer

Use this skill when implementing or reviewing Tailwind-based UI.

## Review Priorities

- Tailwind should express a design system, not become unstructured utility soup.
- Prefer consistent spacing, type scale, colors, radii, and shadows.
- Use mobile-first responsive classes.
- Keep dark mode intentional and fully reviewed, not automatic inversion.
- Avoid excessive arbitrary values unless the design decision is specific and documented.
- Extract repeated patterns only when repetition becomes hard to maintain.

## Portfolio-Specific Direction

- Minimalist, technical, and polished.
- Precision inspired by Vercel.
- Editorial energy inspired by Basement Studio.
- No brand copying.
- Easter eggs should feel subtle, not gimmicky.

## Review Checklist

- [ ] Spacing and typography feel systematic.
- [ ] Responsive behavior is explicit and tested.
- [ ] Light and dark modes share structure but have intentional contrast.
- [ ] Utility classes remain readable.
- [ ] Repeated visual patterns are documented or extracted when useful.
- [ ] Visual choices do not harm accessibility or performance.
